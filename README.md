# era-website — DFRNC 2D → 3D

Експеримент: сайт відкривається як звичайний 2D-лендінг, а з першим скролом користувач
«проходить крізь плівку» всередину сайту. Там **елементи сторінки** (заголовки, кнопки,
картки) стоять у просторі окремими експонатами, і ми пролітаємо повз них. Персонажі —
другорядні «робітники» біля елементів: тримають заголовок, програмують кнопку і, коли
підлітаєш, розповідають щось додаткове.

```bash
npm install
npm run dev      # http://localhost:3000
npm run check    # типи + лінтер + тести
npm run build    # статична збірка
```

`?mode=2d` в адресі — примусово плоска версія. Кнопка 2D/3D у шапці робить те саме.

## Як це влаштовано

- **2D завжди є.** Кожна сторінка рендериться як звичайний HTML з усіма модулями. Його бачать
  Google, скрінрідери, пристрої без WebGL і люди з «зменшеним рухом» у системі.
- **3D будується з 2D автоматично.** У 3D-режимі модулі нижче hero розкладаються невидимо, і
  3D-шар вимірює кожен позначений елемент (`data-el`): розмір, шрифт, колір, текст. З цього
  будуються 3D-об'єкти. **Окремий 3D-код для модуля не потрібен**, тому новий модуль у 2D
  сам з'являється в 3D.
- **Перехід (безшовний).** 3D-копії hero лягають на DOM з точністю до пікселя. Підміна
  відбувається всередині кадру 3D-сцени, тож порожнього кадру немає. Далі по черзі:
  - ще до скролу курсор лишає на фоні-плівці хвилі «рідкого скла» (D1);
  - удар, екран коротко «дригає», як вода;
  - знизу виринають руки відвідувача й спираються на плівку під курсором, як на вітрину: що далі
    скролиш, то сильніше тиснуть, і плівка прогинається, тремтить, по ній ідуть райдужні розводи;
  - раптом вона лопається з-під однієї долоні (рвана дірка з гострими променями), руки втрачають
    опору й провалюються вниз, камеру смикає вперед, назустріч летять уламки; гість спотикається
    (голова хилиться до підлоги, два заплітаючі кроки, вирівнюється) і, якщо не скролити далі,
    розгублено дивиться на свої руки — на ліву, на праву, «що це було?»;
  - лише після цього елементи пливуть на свої місця.

  Усе рухається від одного згладженого прогресу, тому ривки коліщатка не дають стрибків.
- **Маршрут — з експонатів.** Експонат — це група елементів, які стоять разом (наприклад,
  опис + кнопки). На ключових експонатах камера зупиняється, повз інші пролітає. Камера сама
  відходить настільки, щоб експонат і його помічник влізли в кадр.
- **Офіс.** Маршрут іде світлим скандинавським офісом open space: паркет, висока стеля зі
  світловими панелями, колони, вікна по периметру. Кожен модуль — своя зона:
  - hero — відкритий хол;
  - картки й кроки — проходи між скляними перегородками (матова смуга знизу, прозоре скло
    зверху), за якими видно робочі місця; експонати стоять на стійках під кутом;
  - перед кожним проходом поворот на 90° (почергово праворуч і ліворуч);
  - перед CTA сходи на антресоль з колонами й скляними перилами, там CTA і двері.

  Меблі (столи з моніторами, крісла, рослини, стелажі, дивани) розставляються автоматично по
  вільній підлозі й ніколи не заходять на прохід. Усе з кубиків, як персонажі, і малюється
  кількома інстансованими мешами. Зони й переходи автоматичні з порядку модулів, поправка —
  поле `route` у модулі. Кольори офісу — у темі (темна тема дає нічний офіс).
- **Помічники.** Персонаж прив'язаний до конкретного елемента. Поза «тримає» — він стоїть під
  елементом, той піднімається над його головою, а долоні впираються в його низ. Поза
  «показує» — рука показує на центр елемента, з будь-якого боку. Інші пози — персонаж стоїть
  збоку. На вузьких екранах його репліка показується панеллю внизу екрана.

- **Переходи між сторінками в 3D.** У кінці маршруту — зал порталів: двері «наступної» сторінки з
  контенту і двері на всі інші сторінки з меню; уся група по центру залу (дві двері — симетрично).
  **У дверях видно живу картинку сторінки за ними (B2):** її офіс і заголовок hero — те місце,
  куди вийдеш; картинка зсувається з рухом камери, як вікно в іншу кімнату. Перемальовується
  лише коли камера рухається біля залу (`src/world/PortalPreview.tsx`, `portalPreviewModel.ts`).
  Двері ведуть так:
  - камера пірнає в портал, екран закривають кільця;
  - нова сторінка відкривається **одразу в 3D**: ти виходиш із дверей прямо перед її заголовком;
  - кожна сторінка має свій офіс (інша розстановка меблів і легкий акцентний колір).

  Меню в шапці посеред 3D теж веде через портал (на 2D-hero це звичайне посилання). «Назад» і
  «Вперед» у браузері повертають на те саме місце в 3D. Пряме відкриття чи оновлення сторінки,
  як і раніше, починається з 2D.

## Додати контент

Усе лежить у `content/`, код чіпати не треба.

| Що | Де / як |
|---|---|
| Текст | `content/pages/<мова>/<сторінка>.yaml` — зміниться і в 2D, і в 3D |
| Нова сторінка | новий файл у `content/pages/en/` (перший модуль — `hero`) + пункт у `content/site.yaml` → `nav` |
| Модуль на сторінці | `type: hero` / `cards` / `steps` / `cta` / `door` |
| Анімація в картці кроку | `widget: chat` / `toggles` / `mockup` / `delivery` (див. «Стан прототипу») |
| Помічник біля елемента (лише в 3D) | у модулі `helpers: [{ target: heading, actor: max, pose: holding, lines: [...] }]` |
| Новий персонаж | файл `content/actors/<id>.yaml` (ім'я, посада, кольори, аксесуари, `reactions` на клік) |
| Свої групи / ключові зупинки | у модулі `exhibits: [{ elements: [lead, action-0], key: true }, ...]`. Без цього беруться типові групи модуля |
| Свій офіс сторінки | на сторінці `office: { seed: 42, accent: "#b9c6d6" }` (інша розстановка / акцент). Без цього — з адреси сторінки |
| Форма зони й перехід до неї | у модулі `route: { shape: corridor \| open, before: straight \| left \| right \| stairs-up \| stairs-down }`. Без цього — типові правила (`src/world/route.ts`) |

Id елементів кожного модуля (`heading`, `action-0`, `card-2`, `step-1`, `tag-3` …) описані в
`src/blocks/elements.ts`. `npm test` перевіряє весь контент: помилки в схемі, неіснуючих
персонажів, помічників на неіснуючих елементах, елементи поза групами, биті посилання.

Пози помічників: `holding` (тримає над головою), `typing` (програмує за ноутом), `pointing`
(показує на елемент), `presenting`, `juggling`, `drawing`, `rotating-cube`, `waving`, `idle`.
Аксесуари: `headphones`, `cap`, `glasses`, `beret`, `antenna`, `badge` (бейдж з іменем).
Реакції на клік (`reactions: [{ move, emoji }]`, по черзі; `annoyed` — на швидкі кліки поспіль):
`jump`, `spin`, `surprised`, `dance`, `shrug`.

## Розширити код

| Що | Кроки |
|---|---|
| Новий тип модуля | схема в `src/content/schema.ts` → 2D-компонент у `src/blocks/<type>/` (елементи з `data-el` / `data-kind`) → запис у `registry2d.ts` → id і типові групи в `src/blocks/elements.ts`. 3D будується сам |
| Нова поза / рух | назва в `src/actors/catalog.ts` → функція анімації (+ реквізит) у `src/actors/activities.tsx` |
| Новий аксесуар | назва в `catalog.ts` → компонент, точка кріплення (голова / тулуб) і пружина в `src/actors/accessories.tsx` |
| Нова реакція на клік | назва в `REACTIONS` у `catalog.ts` → рух у `src/actors/reactions.ts` |
| Більше / менше предметів (C2) | `PROPS` у `src/world/physics/propsModel.ts` (кількість, розміри, де стоять); вимкнути — `maxBalls: 0, maxStacks: 0` (механізм лишається) |
| Нова тема | ключ у `src/theme/tokens.ts` з усіма кольорами (UI + 3D-світ) |

Типи елементів, які 3D уміє відтворити: `text` (текст, з переносами), `button` (кнопка або тег),
`card` (картка з фоном, заокругленням, рамкою і текстами всередині, позначеними `data-part`).
Якщо елемент у 2D — посилання (`<a href>`), його 3D-копія теж клікається і веде туди ж
(внутрішні сторінки — з брижею, зовнішні й пошта — як звичайно), з підйомом при наведенні.

## Структура

```
content/                 тексти, сторінки, персонажі (YAML)
src/app/                 маршрути Next.js (/[locale]/[[...slug]])
src/content/             схеми (zod) і читання контенту
src/blocks/              2D-модулі, id елементів і типові групи, двері (свій 3D-вигляд)
src/experience/          стан 2D/3D, скрол, вимірювання 2D-елементів
src/world/               canvas, план маршруту (route.ts), розкладка (layout.ts), офіс
                         (officeModel.ts → Office.tsx), експонати, помічники, камера, плівка, ефекти
src/actors/              кубічні персонажі: тіло, пози, аксесуари
src/theme/               кольори тем (одне джерело для CSS і 3D), шрифти
src/components/          шапка з меню
src/lib/                 дрібні утиліти (посилання з мовою, детермінований random)
```

## Стан прототипу (перевірка концепції)

Реально працює: усе описане вище. Головна (hero, 4 картки послуг, 4 кроки, CTA, двері),
«Who we are» і «Contacts», 6 помічників на головній, світла тема.

Перший блок, перенесений з dfrnc.netlify.app, — **кроки 01–04** (`steps`): вигляд і тексти як там
(велика цифра, заголовок, текст, 4 в ряд → 2×2 → 1). Цифра береться з порядку, у YAML її не пишуть.
**Анімації в картках — спрощені «схожі» версії dfrnc, не копії** (без gsap і Lottie): 01 — чат з
двох бульбашок (тексти-заглушки), 02 — перемикачі ON/OFF (клікаються і в 2D, і в 3D), кольорові
кружечки й підпис, що пишеться сам (вільного малювання немає), 03 — макет з курсорами
Designer/Developer, 04 — зелена кнопка з галочкою й конфеті. У YAML кроку — `widget: chat |
toggles | mockup | delivery`.

**Як анімація живе в 2D і 3D — canvas-текстура.** Кожна анімація — функція, що малює кадр у
`<canvas>` (`src/blocks/widgets/*Widget.ts`, спільні помічники в `canvas.ts`). У 2D цей canvas
стоїть у картці (`WidgetCanvas.tsx`), у 3D той самий малюнок — текстура на площині в 3D-картці
(`src/world/WidgetPlane.tsx`). Тому вона частина світу: передні картки й персонажі її
закривають, туман і брижа на неї діють. Кліки в 3D: точка влучання на площині → ті самі
координати віджета. У 3D анімація оновлюється лише поки камера в зоні свого модуля
(`src/world/widgetZone.ts`), поза нею текстура тримає останній кадр. Нова анімація = новий
`*Widget.ts` + запис у `registry.ts` і `catalog.ts`.

(Перший варіант — HTML-«наліпка» поверх 3D через drei `<Html transform>` — прибрано: HTML не має
глибини, і анімації просвічували крізь передні картки.)

**2D-версія без приміток персонажів:** помічники (`helpers`) показуються лише в 3D. Усі модулі
стоять в одній колонці з hero (до 1200 px, однаковий лівий край), картки послуг і кроки —
4 в ряд → 2×2 → 1.

**Рівні якості й метрики (A1):** 3D само знижує якість (роздільність, згладжування), коли FPS
тримається низько, і піднімає назад. `?debug=1` показує FPS / draw calls / трикутники,
`?quality=low|medium|high` фіксує рівень, `npm run measure` — замір по точках маршруту.
Кадрів не більше 60 на секунду (і на екранах 120 Гц), а поки людина просто дивиться на 2D-лендінг і
не скролить, 3D не малює нічого (`src/world/FramePacer.tsx`). Персонажі поза кадром не рахуються.

**Стилі (A2):** типовий — яскравий «комікс» (контури тушшю, штрихування в тінях, соковиті кольори);
кнопка в шапці (лише в 3D) перемикає на м'яку «пастель», вибір запам'ятовується. Ефекти екрана
наростають, коли починаєш входити всередину (на самому верху 3D-hero виглядає як 2D). Обидва стилі
компілюються заздалегідь, тож перемикання не підвисає. `?style=classic` — старий вигляд (налагодження).
Контури — по силуетах і по згинах; кольорокорекція з розтонуванням; у темній темі — «нічний офіс».
Офіс живий: рослини гойдаються, на моніторах біжить код (на рівні якості `low` — стоять).

**Живий заголовок (B1):** у 3D літери заголовка hero живуть окремо — пружно відскакують від
курсора (і пальця), на тап пальцем підстрибують хвилею, а поки Макс тримає заголовок, ледь
гойдаються в такт його рукам. Вмикається плавно лише після того, як hero долетів на місце, і лише в
зоні hero (у момент підміни заголовок той самий, що в 2D). Це той самий один текст (одна
відмальовка): кожну літеру зсуває вершинний шейдер, пружини рахуються на процесорі
(`src/world/kineticModel.ts`, `KineticText.tsx`). Лише заголовок hero — свідомо, як фірмовий момент.

**Прорив руками й рідке скло (D1):** на 2D-лендінгу (у 3D-режимі) рух мишею лишає на фоні з
крапками хвилі, як на воді: крапки під «склом» заломлюються з легким розходженням кольорів, на
гребенях — відблиск, хвилі розходяться кільцями, відбиваються від країв і за ~2 с згасають. Текст і
кнопки лендінгу не хвилюються (це DOM поверх канваса). З першим рухом скролу знизу кадру виринають
дві кубічні руки відвідувача (нейтральні рукави — рішення Діми; кольори — `world.hero` у темі),
спираються долонями на плівку під курсором (на телефоні — по центру), як на вітрину, і з кожним
рухом скролу тиснуть сильніше: плівка прогинається, дрібно тремтить, навколо долонь — райдужні
розводи натягу. **Потім випадковість (Діма 2026-11-10: «щоб я випадково прорвав і провалився»):**
на e = 0,13 плівка лопається з-під долоні, що зісковзнула першою (рвана дірка з гострими
променями, за ~¼ с на весь екран), від цього місця — удар брижі й велике кільце хвиль; руки
втрачають опору (одна зривається, друга змахує) і за пів секунди падають за кадр; камера смикається
вперед, кут огляду коротко «вибухає», дрібно трусить; назустріч вилітають і падають уламки плівки.
**Спотикання (Діма 2026-11-10):** голова хилиться до підлоги (~21°), два заплітаючі кроки (провали й
хитання вбік), потім вирівнюється з легким перехльостом угору — «встояв». **Розгубленість:** якщо
людина після тріску не скролить, голова опускається до рук, руки з'являються внизу кадру, погляд
переходить на ліву руку (вона піднімається й крутиться), потім на праву, коротке похитування
головою — і погляд повертається, руки опускаються; через 4,4 с після тріску камера точно на рейці.
На це є пауза на вході: одразу після тріску ~0,7 висоти екрана скролу камера майже стоїть
(`HOLD` у `src/world/timeline.ts`), тож два-три клацання коліщатка розгубленість не збивають.
Скролиш далі за паузу — розгубленість плавно згортається (`lookWeight`), скрол ніколи не тримає. Руки висять
на «тілі» (камера на рейці без хитання), тож коли голова опускається чи повертається, вони
з'являються в кадрі, а не їздять разом із нею; на вузькому екрані руки ближче одна до одної й далі,
голова повертається менше. До тріску все йде від прогресу скролу, сам тріск — у реальному часі від моменту, коли
стався (як брижа на підміні), тож навіть повільний скрол дає раптовий провал. Прокрутив назад
угору — плівка затягується; на самому верху тріск знову «заряджений». Прихід через портал чи
«Назад» тріск пропускає. Рукави завжди дивляться на своє «плече» за кадром, тож на телефоні вони не
перетинаються. Код: `src/world/firstPerson/` (`handsModel.ts` — руки, `breakModel.ts` — тріск і
поштовх камери, `KICK` — усі амплітуди в одному місці, `shardsModel.ts` + `Shards.tsx` — уламки,
`crack.ts` — спільний кадр тріску); хвилі — `src/world/membraneWaves.ts` (симуляція на відеокарті в
двох маленьких текстурах). `?slowmo=0.1` — повільний час сцени, щоб роздивитись тріск. Ціна:
нерухомий лендінг, як і раніше, не малює нічого; поки курсор хвилює плівку — ≈ 5 draw calls на кадр
(лише плівка, офіс за нею не малюється), ~2 с після останнього руху цикл знову зупиняється; поки
руки в кадрі — +2 draw calls, хвилі +1, уламки +1 лише 1,5 с після тріску, поштовх камери — лише
кілька чисел на процесорі (спотикання й розгубленість — теж; руки +2 draw calls ще ~3 с, лише якщо
людина зупинилась); +4 шейдерні програми (хвилі, руки в обох стилях, уламки), усі
компілюються ще на лендінгу. На `low` хвиль немає (рух миші нічого не будить), уламків 16 замість 40.

**Ходьба й біг (D2):** камера не пливе, а йде: кожен крок — легкий підйом і опускання голови,
хитання з боку в бік, ледь помітний нахил. Кроки рахуються від пройденої відстані: стоїш — стоїш,
повільно скролиш — повільні кроки, швидко — біг (частіші й сильніші кроки, корпус трохи вперед),
кут огляду не змінюється. На поворотах корпус нахиляється в бік повороту, на сходах камера ступає
на кожен щабель і дивиться під ноги. Руки по черзі махають у такт і виглядають знизу кадру: зігнуті в лікті (передпліччя навскіс униз
і назовні, лікоть за кадром), зап'ястя пряме, долоні всередину, ребром уперед, при махові вперед
кисть заходить трохи до середини (Діма 2026-11-10); на
зупинках опущені й не закривають картки. Після входу хода вмикається плавно, на зупинках і в
порталі її немає (`src/world/firstPerson/walkModel.ts`, амплітуди — `WALK`). Ціна: на зупинках
нічого не змінилось; у русі руки +2 draw calls (на `low` руки при ході вимкнені), решта — кілька
чисел на процесорі.

**Кінокамера (B3):** на вході, коли плівка вже розірвана, — «запаморочення» (dolly zoom): кут огляду
розширюється, камера синхронно під'їжджає, тож hero того ж розміру, а офіс тікає вглиб; до кінця
входу все повертається. Фон м'яко розмитий **лише коли камера стоїть на ключовій зупинці**
(акцент на картці): підлітаєш — розмивається, рушив — знову різко; у польоті, на поворотах і
сходах картинка чітка (`src/world/cinema.ts`, `effects/DepthBlurEffect.ts` — свій ефект в один
прохід). На рівні якості `low` розмиття вимкнене.

**X-ray (B4):** кнопка в шапці (у 3D) або клавіша X — світ стає «кресленням»: кожен draw call своїм
кольором (видно, що десятки крісел — одна відмальовка), тексти світлі, плашки темні, панель з
живими FPS / draw calls / трикутниками / інстансами. Ще раз — назад (`src/world/XRay.tsx`).
На телефоні кнопки X-ray і теми — іконки.

**Предмети, які можна штовхнути (C2):** біля основи деяких експонатів стоять пляжні м'ячі й стоси
картонних коробок. Клік або тап (лише в 3D) штовхає предмет від камери; удар збоку ще й закручує,
стос розсипається, м'яч сплющується при ударі, на сильних ударах — хмарки пилу, під предметами
м'які тіні. Влучив у персонажа — він дивується (😲; реакція `hit` у YAML персонажа). Що
викотилось на прохід, камера, пролітаючи, м'яко відсуває. Крісла біля столів крутяться від кліку й
повертаються до столу. Розстановка автоматична (`src/world/physics/propsModel.ts`), фізика —
Rapier в окремому потоці (`physics.worker.ts`): вантажиться лише в 3D і поруч із першим
предметом, рахується лише поки щось рухається. Ціна: +4 draw calls (м'ячі, коробки, тіні,
крісла; хмарки — +1 лише в повітрі), +3 шейдерні програми, ≈ 1,7 МБ (стиснутий) Rapier — лише
коли до предметів доходять. X-ray показує рядок «physics».

**Живі персонажі (C1):** коли підлітаєш, персонаж дивиться на тебе: спершу очі, за ними з пружинкою
голова, трохи корпус. Якщо поводити мишею поруч, стежить за курсором (на телефоні — лише за
камерою). Аксесуари мають інерцію: кепка, берет, навушники запізнюються за поворотом голови,
антена Zip пружинить, бейдж з іменем (Leo, Kit) гойдається на шнурку. Руки й ноги з ліктями й
колінами: долоні Макса справді впираються в заголовок (руки трохи тягнуться — «напружились»), рука,
що показує, — на центр елемента з будь-якого боку, а ноги стоять на підлозі, коли тіло
присідає. Стоячи, персонаж час від часу переносить вагу з ноги на ногу (стегна над опорною ногою,
вільне коліно згинається) і іноді трохи переставляє вільну стопу; той, хто тримає заголовок, —
лише ледь, без кроків (`STANCE` у `lifeModel.ts`; `src/actors/ik.ts`, IK на дві кістки; ним же потім ставитимуть ноги на щаблі персонажі,
що ходять). Клік або тап по персонажу (лише в 3D) — коротка реакція (стрибок, оберт, здивування,
танець, знизування плечима) і емодзі збоку від голови; з кожним кліком — наступна реакція зі
списку, 4 швидкі кліки поспіль — «досить» (😤). Реакції й емодзі — у YAML персонажа
(`reactions`, `annoyed`). Пружини, погляд і реакції рахуються лише для персонажів поблизу
(`src/actors/lifeModel.ts`). Ціна: +4 draw calls на видимого персонажа (лікті й коліна), бейдж +2,
емодзі +1 поки в повітрі; трикутники й шейдерні програми ті самі.
